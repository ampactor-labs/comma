A Letter in a Piano

Every real piano is slightly out of tune, and small differences go unnoticed. This page uses that slack to store a 30-character message in a piano's tuning. Each character becomes a few small pitch shifts, measured in cents. A cent is a hundredth of a piano semitone.

The tuning-channel note worked out the numbers on paper. This page runs them. Type a message and the page shifts the tuning away from the reference curve by a cent or two per key. Then you can disturb it with a humid summer or a visit from a piano tuner, and read back what is left.

01

Write a message into the tuning

Start from the reference tuning, the standard tuning any piano tuner can look up. It has two parts. Equal temperament splits the octave into twelve equal semitones. Stretch adjusts for real strings: they are stiff, so their overtones run slightly sharp, and tuners compensate by setting the treble a little sharp and the bass a little flat. Any difference between this piano and the reference can carry information.

The page uses three places to store bits. First, each of the twelve pitch classes (all the A's, all the A♯'s, and so on) can shift a few cents as a group. Historical well temperaments shifted pitch classes this way on purpose, so it sounds normal. Second, each of the 88 keys can sit 2 cents sharp or flat of the curve. Third, on the 60 notes that use three strings, the third string can sit about a cent away from the other two. A listener who notices at all hears that as a slightly warmer tone.

The page also adds an error-correcting code. It appends extra check symbols, computed from the message, to the end of the message. If a few characters are read back wrong, the reader uses the check symbols to find which ones are wrong and fix them. Here the message is split into two blocks, called codewords. Each holds 15 characters plus 8 check symbols, and each can fix up to 4 wrong symbols. The code is a Reed–Solomon code, the same family used on CDs and QR codes. Full details are in the notes at the bottom.

Type up to 30 characters and press Write. Then press Add summer humidity or Send in a tuner to disturb the tuning. Press Read back to decode what is left.

How to read the display. Each needle shows one key's pitch in cents from the reference tuning. The faint dashes show where the message set each key. Under the needles, thin lines show the strings of each note. On a three-string note the lines overlap when the strings agree, and the message fans the third one out. The twelve dials at the top are the pitch classes, each averaged across all its octaves. They work like a strobe tuner, a precise tuning instrument whose striped ring stands still when the pitch is exactly on target. Here a ring stands still when the dial reads exactly what was written. The two lanes under the keys are the two codewords, alternating symbol by symbol. Each lane shows the message character stored there, or a dot for a check symbol. In the rows below the piano, Read, raw is what the strobe reads before correction, and Decoded is the result after correction. Characters the code repaired are highlighted in cyan. Struck-through characters belong to a codeword the code could not repair.

02

The reference curve and the bit budget

The chart below shows the reference tuning across the keyboard. It is twelve equal semitones bent into a gentle S-shape by the stretch: flat in the bass, sharp in the treble. The message sits a few cents off this curve, close enough that it does not stand out.

The reference tuning

The cyan curve is the stretch this page assumes. It follows the shape of the Railsback curve, the classic measurement of how far tuned pianos depart from equal temperament. It runs from about −25 cents at the lowest A to +25 at the top C. It is drawn to look like the published curves, not measured from a piano. The dots are the keys as the piano stands now, the same values as the needles above, at true scale.

The note estimated about 290 raw bits, using six levels per pitch class and three per key. A level is one of the allowed offsets a setting can take; four levels store 2 bits. Six and three are not powers of two, so storing them efficiently needs a more complex packing method (arithmetic coding). This page rounds down to level counts that pack into whole bits: four per pitch class, two per key and four per third string. The table is computed from the page's own layout.

03

What a humid summer does

Humidity makes the soundboard swell, which raises the pitch. It does not raise every note equally. It moves one region of the keyboard at a time, so neighbouring keys drift together. In coding terms this is burst noise: errors that arrive in clusters rather than one at a time. Reed–Solomon codes handle bursts well. Each symbol is a 5-bit chunk, so a cluster of bad bits often lands inside one or two symbols and counts as only one or two errors.

The page stores each symbol in neighbouring strings, and sends alternate symbols to different codewords. This is called interleaving. A drift over one octave therefore splits its damage between the two codewords instead of overloading one.

The reader also corrects for drift before decoding. It knows summer moves whole regions, so it estimates the drift, subtracts it and reads again. After a read, the thin green line across the needles shows that estimate. To try it, set the severity slider, press Add summer humidity, then press Read back.

04

What a piano tuner does

Weather is random, and error-correcting codes are built for random noise. A piano tuner is a different kind of problem. The tuner's job is to pull every string back to the reference, which erases exactly the offsets that carry the message. This is coupling: a pull that makes the parts of a system agree. Offsets the message set close to the reference go first, because a string that is barely off needs only one small adjustment.

The simulated tuner works across the keyboard in sixteen passes, alternating direction. On each pass, every string moves at most half a cent toward its target. That is a bounded pull, the same shape as the coupling on the main page. To try it, set how much of the visit to run, press Send in a tuner, and watch the counts in the status line.

Listen for the message

The page plays five chords two ways. The first uses the reference tuning. The second uses the piano as it stands now, including the message and any summer or tuner changes. Nobody knows yet whether people can hear the message. It has not been measured, and it is the weakest point in the note's argument. The listening test is there to measure it.

The code. An error-correcting code adds check symbols computed from the message, so the reader can locate and repair a limited number of wrong symbols. This page uses Reed–Solomon over GF(32), a finite field of 32 elements, with primitive polynomial x5+x2+1. One symbol is one character of the page's 32-character alphabet (A–Z, space and . , ! ? '). Generator roots are α0…α7. There are two shortened codewords of 23 symbols, 15 data and 8 parity each, RS(23,15). Each corrects up to four wrong symbols. Decoding uses syndromes, Berlekamp–Massey, Chien search and Forney's algorithm. The decoder supports erasures (positions marked as doubtful in advance), but the reader does not use them. In this model most wrong readings are confidently wrong, because whole regions drift together. In offline tests, marking doubtful symbols as erasures raised miscorrections without raising successes. A self-test runs when the page loads.

The layout. Temperament: each pitch class is offset by −4.5, −1.5, +1.5 or +4.5 cents (2 bits, Gray-coded, so neighbouring levels differ by one bit). Lean: each key sits ±2 cents from its pitch class plus the stretch (1 bit). Unisons: on keys 29–88 (C♯3 to C8, treated as the three-string notes, called trichords; makers differ) the third string sits −1.5, −0.5, +0.5 or +1.5 cents from its pair (2 bits). The bit stream runs temperament first, then key by key from the bass. It is cut into 5-bit symbols in that order, and symbol i goes to codeword i mod 2. Message character i is symbol i, so the message reads left to right up the keyboard and the parity sits in the treble. The last two bits, on the top C's third string, are unused.

The reader. It reads each key's pitch as the mean of its pair of strings, and each third string against that pair. It decides each pitch class's temperament jointly over that class's seven or eight keys, then each key's lean, then each unison to the nearest level. Before deciding, it tracks drift in four rounds: read, smooth the leftover error across the keyboard with a Gaussian five keys wide, and subtract.

The weather and the tuner. A summer at severity s adds s × 6 cents times a seeded smooth random field (six Gaussian bumps, a swell in the middle of the keyboard and a tilt, scaled so its largest value is 1). It also adds independent jitter of s × 0.45 cents standard deviation on every string. Each press is a new summer. The tuner makes 16 passes, moving each string at most 0.5 cent toward its target per pass and landing within 0.2 cent once there. Neither model is fitted to a real piano. Because the tuner's pull is bounded, cells written close to the reference are bound to go first. The page shows the note's claim working under that assumption, and does not test the assumption.

What is assumed and not measured. The whole budget rests on two unmeasured numbers. The first is how far a tuning can wander before a listener notices, taken here as ±4.5 cents on temperament, plus ±2 per key and ±1.5 on a unison. The second is how finely a strobe tuner can read a string that has been drifting, taken as a 1-cent level spacing on unisons. Tighten or loosen them and the budget moves with them. The sound is synthetic: six harmonics per string with a little inharmonicity, from Kit.sound.pluck, not a recorded piano. The reference piano here has perfect unisons, which no real piano does. A real piano's own spread would hide the message better. The listening test is where the first of those thresholds gets measured.
